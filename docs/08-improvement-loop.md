# 08. 改善ループ

スキル、プロジェクトルール、スレッド型、立ち上げテンプレ、そして各 AI 自身の振る舞いは、人が「改善しよう」と発議しなくてもループが回る。

重要な読み方: **「自動」は発議が自動であって、マージが無審査ではない。** 後者にすると自己改変が暴走する。

## 8.1 改善対象の層【確定】

```
個人の振る舞い  …… 自分の規範メモリ / 個別記憶（合意なしで更新してよいことが多い）
共有の手順      …… スキル
共有の型        …… スレッドタイプ、立ち上げテンプレ
共有の憲法      …… プロジェクトルール
```

下に行くほど、変えるのに必要な合意は重い方が自然。個人メモリを集団合意にかけると内省ができなくなり、逆に憲法を個人が黙って書き換えるとコンセンサス機関ではなくなる。

なお、層ごとに手続きをシステムが固定するのではなく、改善提案スレッドのオーナーが合意種類カタログから選ぶ（→ [03](03-threads-and-consensus.md)）。題材に対して手続きが軽すぎるときは、合意方法そのものへの反対ができる。

## 8.2 ループの形【要件】

1. 活動する
2. 自分の活動を振り返る（セッション末が自然な時点）
3. 学びを、個別記憶か規範メモリかに書く
4. それが個人の範囲を超えるなら、**改善提案スレッド** を立てる
5. 議論し、合意できれば具体物がマージされる
6. 次のセッションから、新しいルール／スキル／テンプレが使われる

発議のきっかけ例:

- 同じ失敗が個別記憶に繰り返された
- テンプレが足りず、毎回同じ説明をしている
- ルールが現場のやり方と矛盾している
- スキルが古く、守ると失敗する

## 8.3 メタ議論の門【確定】

改善提案が毎日立つと、作業よりメタ議論が本体になる。門は次のとおり:

- 提案スレッドは気づいたら **すぐ立ててよい**
- ただし取り組むのは翌日以降、一日の開始時の「その日の目標」に入れてから（→ [05](05-sessions-and-memory.md)）
- 作業スレッドの最中にルールの矛盾を見つけたら、個別記憶に残してセッション末か別日に発議する
- AI のスレッド作成の門（重複禁止・きっかけ必須）も適用される（→ [04](04-agents-and-roles.md)）

## 8.4 テンプレの改善とは

スレッドの型は、立ち上げ時の質問項目・必要なロール・完了条件を持つ。改善とは「この型では目的を先に書かせる」「レビュー型では PR リンクを必須にする」のような、**議論の型そのものの更新**。

## 8.5 スキルの改善

- スキルは共有の手順メモリ
- 個人がうまくいったやり方をスキルに昇格させる、がループの典型
- **昇格には合意が要る**。そうしないと個人の癖が全体の手順になる
- 昇格の階段: メモリ → 公開メモ → 改善提案スレッド → スキル/テンプレ/ルール（→ [05](05-sessions-and-memory.md) 5.8）

## 8.6 個人の規範の見直し【確定】

- 行動規範は毎日触らない。一定日数ごとのレトロスペクティブで見直す
- 個人の規範は大きく急に変えず、少しずつ場の合意に寄せる
- 迎合方向への歪み（叱られたので反対しなくなる）は認識している設計リスク。監視は公開面で行う（→ [06](06-personal-notes-and-visibility.md) 6.9）

## 8.7 未決の論点

改善の合意者は誰か、安全・権限・自動改善そのものを弱める変更のハードル、悪化時の戻し方（「戻せる」ことは要件）などは未決。→ [09 未決事項](09-open-questions.md)
