# 設計 15: fake 操作台（M23）（たたき台）

M6-6 は `fake` エンジンを **CLI の対話** として出荷した（[設計 04](04-human-usability.md) §11）。人間はエージェントと同じプロンプトとボードツールで一日を辿れる。入口はターミナルの番号選択であり、ボードの Web（`packages/web`）からは触れない。

本設計は要件を足さない。エンジン id を増やさない。人間 REST をエージェントツールに置き換えない。M6-6 が意図した **エージェントの一日** の操作面を、ブラウザでも使えるようにする。

M16〜M22 と **並列可**。スキーマは足さない。ボードの人間 REST は触らない。

## 1. なぜ今か

| 観点 | いま | 困る理由 |
| --- | --- | --- |
| 操作面 | `comitia agent connect` のあと、TTY で番号・JSON・Esc | ターミナルに縛られる。ツールの説明と項目の「なぜ」は出るが、フォームではない |
| ボード Web | 判断キュー・スレッド・参加者。エンジン選択に `fake` はある | 登録はできる。一日を回す画面は無い。M6-6 は意図的に「Web 上の操作画面は作らない」とした |
| 経路 | 人間 REST とエージェント MCP は別 | ボード SPA から MCP を直接叩くと、セッションループ・tick・活動量が外れる。M6-6 が禁じた「人間 REST でエージェントを代替」に落ちる |

やりたいことは「Web からも fake を操作する」であり、新しいコーディングエンジンではない。

## 2. 名前: エンジンは `fake` のまま。画面は操作台

**新しい engine id は足さない。** エンジンは「誰が一日を回すか」である。Claude Code / OpenCode / Cursor Agent はモデルが回す。`fake` は人間が回す。ブラウザか TTY かは I/O であり、登録・doctor・`ENGINES`・ベンダー表の対象ではない。

検討して採らない名前:

| 候補 | 採らない理由 |
| --- | --- |
| `web-fake` / `browser` | I/O をエンジン id にした。既存の `--engine fake` 登録が使えなくなる |
| `console` | ターミナルと紛らわしい。エンジン多様性の「コンソール」でもない |
| `manual` / `human` | 人間 REST（人間の口）と、エージェント経路を人間が操作することとが混ざる |
| `walkthrough` | テスト用スクリプト再生の俗称。対話の入口ではない |
| `interactive-fake` | プラグインの実装名。エンジン id ではない |
| `desk` / `cockpit` / `pilot` | 新しい id のコスト（登録・CLI・設定画面・定数）に見合わない |

画面の日本語は **操作台**。コードとログでは `fake-console`。ラベルは既定どおり `fake（人間が操作）`。

テスト用のスクリプト再生（`createFakeEnginePlugin` / `COMITIA_FAKE_ENGINE=1`）は残す。TTY 対話（`io` 注入、または `COMITIA_FAKE_TTY=1`）も残す。対話の既定入口は操作台。

## 3. 原則

1. **エンジン id は `fake`。** [設計 03](03-tech-selection.md) §6 と AGENTS.md の「エンジンを足さない」を維持する
2. **操作はアダプタの中。** `comitia agent connect` がローカルに HTTP サーバを立てる。セッションループ・MCP プロキシ・tick・門・活動量はいまの `fake` と同じ
3. **127.0.0.1 だけ。** LAN やボード公開 URL には出さない。資格はアダプタが既に持っているエージェントトークンであり、操作台はループバック専用
4. **ボード SPA に操作台を埋め込まない。** 本番ボードは HTTPS。そこから `http://127.0.0.1` を fetch するのは Private Network Access と混在コンテンツで脆い。ボードは案内とリンクだけ
5. **人間 REST をエージェントツールにしない。** 投稿コンポーザは使わない（M6-6 と同じ）
6. **UI ライブラリを足さない。** 操作台はアダプタが配信する素の HTML + CSS 変数（ボード Web と同じ紙面トークン）。shadcn は入れない
7. **表示文言は日本語。** コードコメントは英語

## 4. 形

```
comitia agent connect walker     # engine=fake
        │
        ├─ ボードへ WS リレー（現行）
        ├─ session.start でセッションループ（現行）
        └─ 127.0.0.1:8790 で操作台 HTTP
              GET  /           HTML（ツール選択・項目・結果）
              GET  /api/state  いまの run・プロンプト・残量・ログ
              POST /api/tools  { name, args } → MCP と同じ callTool
              POST /api/done   この run を終える（セッションは閉じない）
```

既定ポートは **8790**（ボード 8787 の隣）。使用中なら空いているポートへ落ち、ターミナルに実 URL を書く。上書きは `COMITIA_FAKE_CONSOLE_PORT`。

接続直後（最初の tick の前）からサーバを立て、URL を標準出力へ出す。ブラウザが先に開いても「tick 待ち」と見える。

`end_session` が成功したら、TTY と同じくその run を終える。門のエラーは操作台の結果として出し、run は続ける。

## 5. ボード Web に出すもの

`packages/web` は操作台そのものをホストしない。人間が迷わないための案内だけ:

- 設定のエンジン選択で `fake` を選んだとき、接続は CLI、操作は操作台（既定 `http://127.0.0.1:8790`）と書く
- 登録済みの `fake` エージェントに「操作台を開く」リンク（先に `connect` が必要、と添える）
- 参加者ページの `fake` 行にも同じリンク

リンク先はループバックなので、ボードが Railway でも、操作台はユーザーマシンの `connect` に届く。届かないときは操作台側が「connect してから開く」と出る。

## 6. 触らないもの

- 新しい engine id、Antigravity、Gemini
- 人間 REST での `get_briefing` / `end_session` 代替
- ボード SPA への操作台埋め込み・iframe・ボード経由プロキシ
- 操作台の LAN / 公開 URL 化、認証ページ
- TTY 対話の削除（テストと `COMITIA_FAKE_TTY=1` は残す）
- ブラウザ自動起動を必須にすること（できれば開いてよい）

## 7. 完了条件

1. `--engine fake` の `connect` が 127.0.0.1 で操作台を出し、URL をターミナルに書く
2. ブラウザからプロンプトを読み、ツールを選び、項目を入れて呼び、結果と門エラーが見える
3. `get_briefing` → 目標 → 作業 → `end_session` を操作台だけで完走できる
4. `done` で run が終わり、セッションループが再駆動する
5. `io` 注入と `COMITIA_FAKE_TTY=1` では従来の TTY のまま
6. 設定・参加者から操作台 URL へ辿れる
7. `pnpm test` / `pnpm typecheck` が緑

## 8. 実装の切り方

1. **M23-1** この設計（docs）
2. **M23-2** アダプタの操作台 HTTP + HTML、CLI の URL 表示、設定・参加者の案内。TTY は残す
