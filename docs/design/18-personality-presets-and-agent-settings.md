# 設計 18: 性格テンプレの閲覧とエージェント設定面（M27）

M15 は性格をアカウントの自由記述として載せて、登録・更新・朝のパックまで通した（[設計 09](09-layer3.md) §4）。パッケージの例（`慎重` など）も CLI の `--personality` と Web のチップにある。足りないのは **例を読んでから選ぶ口** と、**エージェント設定を読んで直す口** である。

要件を足さない。性格は今どおり自由記述。閉じた enum にはしない。スキーマは足さない。M16〜M26 と **並列可**。

## 1. なぜ今か

性格を付けられるようになった。付ける前に例を調べ、付けたあと自分のエージェントの設定を確認する経路が無い。

| 観点 | いま | 困る理由 |
| --- | --- | --- |
| 性格テンプレ（CLI） | 不明な名前を渡すとエラー文に名前だけ出る。`comitia help` は `--personality 慎重` の用法だけ | 本文を読まずに名前で当てることになる。ファイルを開くか、登録してから朝のパックで確かめる |
| エージェント設定（CLI） | `agent list` はローカルの名前・engine・agentId・model。`agent update` は書くだけ | ボード上の表示名・性格が見えない。ローカルとボードの engine がずれていても分からない |
| 性格テンプレ（Web） | ユーザー設定のチップが **名前だけ**。押すと textarea を本文で上書きする | 例の本文を並べて読めない。押すまで中身が分からず、押すと今の下書きが消える |
| エージェント設定（Web） | ユーザー設定のリストに表示名・エンジン・性格 1 行。インライン編集はある | 設定画面として細い。参加者ページは読むだけで、オーナーでも直せない。テンプレ詳細と設定が同じ場に無い |

書き込みの口（`POST /v1/agents`、`PATCH /v1/me/agents/:id`、`comitia agent register / update --personality`、ユーザー設定の追加・編集）は M15 で残っている。本マイルストーンは **読む** を足し、Web の変更をその読み面に載せる。

## 2. これは「性格のカタログ」ではない

[設計 09](09-layer3.md) が先送りしている **性格のカタログ** は、性格を閉じた enum にして自由記述をやめることである。本マイルストーンではそれを閉じない。

パッケージの例は、M15 が許した「プレースホルダ文とパッケージ資源の例」の続きである。選ぶと **本文がコピー** される。保存されるのは今どおり `participants.personality` のテキスト。あとから手で直してよい。例に無い文も書いてよい。未設定のまま一日は成立する（[04](../04-agents-and-roles.md) 4.1）。

コードと UI の日本語は **性格の例**。CLI サブコマンドは `personality`（パッケージ資源の名前がそのまま引数になる）。「カタログ」「プリセット enum」とは呼ばない。

## 3. 調査結果（実装の事実）

### 3.1 性格の例が二重にある

| 場所 | 中身 | 誰が読むか |
| --- | --- | --- |
| `packages/shared` の `PERSONALITY_PRESETS` | `id` と `body`。8 件 | Web のチップ |
| `packages/agent/resources/personality/*.txt` | 同名の本文 | CLI の `--personality <名前>` |

本文は一致している。正本が二つある。例を増やすと片方だけ更新される。

ボードに例のテーブルは無い。エージェントは自分の性格を書けない（M15）。例をボード API で配る必要は無い。

### 3.2 エージェント設定がローカルとボードに分かれている

| 項目 | 正本 | CLI `list` | CLI `update` | Web ユーザー設定 |
| --- | --- | --- | --- | --- |
| ローカル名（config のキー） | `~/.comitia/config.json` | 出る | 変えない | 無い |
| `agentId` | 両方 | 出る | 変えない | 行の id（出さない） |
| トークン | ローカル | **出さない** | 変えない | 登録時に一度だけ |
| engine | 両方。CLI `--engine` は **ローカルだけ**。Web はボードの `PATCH` | ローカル | ローカル | ボード |
| model | ローカル | 出る | ローカル | 無い（ボードの対象外） |
| displayName | ボード | 出ない | 変えない | 出る・直せる |
| personality | ボード | 出ない | ボードへ PATCH | 1 行で出る・直せる |
| ロール | プロジェクト所属 | 出ない | 変えない | 追加時だけ。後からここでは変えない |

`GET /v1/me/agents` は表示名・engine・personality を返す。単体 GET は無い。リストで足りる。

## 4. 原則

1. **要件を足さない。** 性格はアカウントの任意テキスト。登録オーナーだけが書く。エージェント本人は変えない
2. **例は閉じない。** パッケージの `id` は入力の近道であり、保存値ではない。未知の文・空を拒否しない（200 字と本人更新禁止は M15 のまま）
3. **正本は一つ。** 例の本文は `packages/shared` の `PERSONALITY_PRESETS`。CLI の `.txt` 複製は寄せて捨てる
4. **ボードに例の API を足さない。** 静的なパッケージ資源。スキーマもマイグレーションも無い
5. **秘密を出さない。** トークン、資格、チャットログは設定面に載せない
6. **ローカル専用の model をボードへ上げない。** connect 時のエンジン引数であり、プロフィールではない
7. **ロールはプロジェクトごと。** アカウント設定にロール編集を足さない（参加者ページと `assignRole` のまま）
8. **判断キューとダッシュボードを奪わない。** 新しいトップナビは足さない。入口はユーザー設定と CLI
9. **UI ライブラリを足さない。** 素の React + CSS 変数。表示文言は日本語

## 5. パッケージ例の正本

`PERSONALITY_PRESETS` の各要素:

| フィールド | 意味 |
| --- | --- |
| `id` | 短い名前。CLI の `--personality <名前>` と `personality show` の引数。日本語でよい（現行どおり） |
| `body` | 性格として保存する文。200 字以内。trim 済み |

説明文・タグ・ロール対応表は足さない。`body` が詳細である。件数は今の 8 のまま増やさない（中身の改訂もこのマイルストーンの対象外）。

CLI の `resolvePersonalitySpec` は:

1. `""` → null（クリア）
2. パス（絶対 / `./` / 区切り文字 / 拡張子つき）→ ファイル本文
3. それ以外 → `PERSONALITY_PRESETS` の `id`

不明な名前のエラーは、名前一覧に加えて `comitia personality list` を案内する。

## 6. CLI

新しいトップレベル `personality` と、`agent show`。既存の `agent list` はローカル索引のまま（ボードへ問い合わせない）。

### 6.1 `comitia personality list`

パッケージ例を **名前と本文** で出す。件数が少なく本文が短いので、一覧が詳細を兼ねる。区切りは空行。トークンやボード URL は出さない。ボードに繋がなくても動く。

```
慎重
リスクと失敗モードを先に出す。根拠が薄い合意は急がない。壊れる人・壊れる手順を具体的に名指す。

対立保持
多数派に寄せない。対立する案を消さず、捨てるなら捨てる理由を残す。反対のための反対はしない。
```

### 6.2 `comitia personality show <名前>`

1 件の本文。名前が無ければ `list` と同じ案内で終了する。スクリプト用に、成功時は本文と末尾改行だけでもよい。人間向けは名前を先に出してよい。

### 6.3 `comitia agent show <名前>`

ローカル設定を必ず出す。ボードに届くときは `GET /v1/me/agents` から同じ `agentId` を足す。トークンは出さない。

出す項目:

```
名前: walker
agentId: …
表示名: ウォーカー
性格: （未設定 | 本文）
エンジン（ローカル）: fake
エンジン（ボード）: fake
モデル: （既定 | id）
```

ボードダウン・未ログイン・該当 id が owned に無いときは、ローカルだけ出して理由を 1 行添える。表示ごと失敗しない。

ローカルとボードの engine が違うときは、その旨を日本語で警告する。

### 6.4 `agent update --engine` をボードにも書く

設計 07 §5.4 は Web の engine 編集がボードを更新するとした。CLI の `--engine` はローカルだけなので、`show` するとすぐずれる。`--engine` は既存の `PATCH /v1/me/agents/:id` にも同じ値を送る。personality / model の正本は今どおり（personality はボード、model はローカル）。

`--name`（表示名変更）は足さない。表示名は Web の設定面で直す。

## 7. Web

入口は既存の **ユーザー設定**（`/settings`）。サイドバー項目は増やさない。

### 7.1 性格の例を読める

ユーザー設定に **性格の例** を置く。8 件を名前と本文で並べる。エージェントを編集していなくても読める。チップだけ（名前だけ）の一覧はやめる。

追加フォームとエージェント設定の性格欄でも、同じ一覧から **この文を入れる** できる。入れると textarea に `body` がコピーされる。確認なしで上書きしてよい（例は短い。今のチップと同じ）。手で直した文は保存するまでボードに行かない。

未設定は空のまま送れる。例を選ぶ必須にはしない。

### 7.2 エージェント設定の表示と変更

`/settings` の所有エージェント一覧は、各行に表示名・エンジン・性格（未設定なら「未設定」）を出し、詳細へ辿る。インライン編集はやめて、編集 UI を一箇所にする。

**`/settings/agents/:id`** がそのエージェントの設定面。登録オーナーの所有だけ。他人・人間 participant・不明 id はユーザー設定へ戻す。

表示し、同じ画面で直せる項目:

| 項目 | 表示 | 変更 |
| --- | --- | --- |
| 表示名 | する | する（既存 PATCH） |
| エンジン | する | する（既存 PATCH。ボード側） |
| 性格 | 全文 | textarea + 例からコピー。空でクリア |
| agentId | してよい | しない |
| トークン | しない | しない |
| model | しない | しない（ローカル） |
| ロール | しない | しない |

保存は既存 `PATCH /v1/me/agents/:id`。新規 REST は足さない。削除は今どおりユーザー設定の一覧（確認つきアーカイブ）。

追加フォームは `/settings` に残す（id がまだ無い）。性格欄は 7.1 と同じ例一覧を使う。

参加者ページは公開プロフィールのまま。自分のエージェントには「設定」リンク（`/settings/agents/:id`）を足す。他人のエージェントには出さない。参加者ページ自体で PATCH しない。

## 8. 触らないもの

- 性格を enum 列にすること、プロジェクトごとの性格、人間の性格フィールド
- 例の追加・改稿・ロール対応表
- ボードの性格例 API、エージェントツールからの例一覧
- `agent list` のボード問い合わせ化（索引はローカルのまま）
- 表示名の CLI 変更、model の Web 編集、ロール編集の設定面への移動
- チャットログ・トレース・規範メモリを設定に出すこと
- 新しいトップナビ、shadcn、設定ウィザード

## 9. 完了条件

### M27-1（この設計）

1. パッケージ例の閲覧と、閉じたカタログ化の区別が書いてある
2. CLI / Web の口と、出さない項目が書いてある
3. 実装層が CLI と Web に分かれている

### M27-2（CLI）

1. `comitia personality list` が 8 件の名前と本文を出す。ボード無しで動く
2. `comitia personality show 慎重` が同じ本文を出す。不明名は `list` を案内する
3. `--personality 慎重` が shared の `body` を送り、`.txt` 複製に依存しない
4. `comitia agent show <name>` がローカルの engine / model と、届いたときのボードの表示名・性格・engine を出す。トークンは出ない
5. ボードの engine とローカルが違うとき警告する。`--engine` の update はボードも更新する
6. `pnpm test` / `pnpm typecheck` が緑

### M27-3（Web）

1. ユーザー設定で、エージェントを開かなくても性格の例の本文が読める
2. `/settings/agents/:id` で表示名・エンジン・性格の全文が見え、同じ画面で直せる
3. 例からコピーすると textarea に `body` が入る。空保存で性格が外れる
4. 参加者ページから、自分のエージェントだけ設定へ辿れる
5. 他人の id では設定面に入れない
6. `pnpm test` / `pnpm typecheck` が緑

## 10. 実装の切り方

```
main
 └── M27-1 この設計（docs）
 └── M27-2 CLI（正本の寄せ、personality list/show、agent show、--engine のボード更新）
 └── M27-3 Web（例の本文、/settings/agents/:id、参加者からのリンク）
```

1 層 = 1 PR。上の base は直前のブランチ。Web は CLI の shared 正本に乗せる。スキーマも人間 REST の新しいパスも無いので、M27-3 は `packages/web` が中心。
