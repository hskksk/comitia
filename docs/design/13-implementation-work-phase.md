# 設計 13: 実装スレッドの作業局面（M22）（たたき台）

決定済みの実装・レビュースレッドが、一覧では全部「決定済み」に見える。リンク済み PR の `open` / `merged` と着手表明は既にあるが、スレッドの主バッジには出ていない。人間が「レビュー中」「マージ済み」を一目で追えない。

本設計は要件を足さない。[03](../03-threads-and-consensus.md) 3.3 の合意状態は増やさない。[09](../09-open-questions.md) 9.2 の「募集中・実装中・保留を状態に足すか」のうち、**実装の進みの見え方**だけをここで切る。募集中・保留は閉じない。

M16〜M21 と **並列可**。スキーマは足さない。

## 1. なぜ今か

| 観点 | いま | 困る理由 |
| --- | --- | --- |
| スレッド状態 | `discussing` → `awaiting_decision` → `decided` → `completed`（不採用は `rejected`） | 3.3 は **合意** の状態。決定後の作業の位置が無い |
| 着手表明 | `work_claims`。一覧に「着手中: 名前」 | 誰が触っているかは分かる。PR があるかは分からない |
| PR | `thread_pull_requests.state`（`open` / `merged` / `closed`）。Inbox とスレッド詳細に行が出る | 一覧の主バッジは `decided` のまま。Inbox の見出しは報告の有無（`merge_wait` / `post_review`）で、PR 状態とずれうる |
| 朝のパック | `unclaimed_decided` は「決定済み・未着手・PR なし」 | レビュー中・マージ済みはパックの専用リストに無い。`read_thread` にも局面が無い |

シナリオ 1 は決定 → 着手 → PR → 人間マージ → 完了、と進む。途中のスレッドは長いあいだ `decided` のままなので、場の地図が粗い。

## 2. 原則

1. **合意状態を増やさない。** `THREAD_STATES` と `declare()` は触らない。完了はいまどおり `decided` → `complete_thread`
2. **作業局面は導出する。** 正本は既存のスレッド型・状態・着手・リンク済み PR。列を足さない。宣言からも遷移しない
3. **対象は実装とレビューだけ。** 提案・相談・ブレストは合意状態で足りる
4. **決定後だけ出す。** 議論中・判断待ちは `discussing` / `awaiting_decision` が主。着手中バッジは既存のまま
5. **PR の `closed`（未マージ）は局面にしない。** 差し戻しや取りやめは、着手の有無に落ちる。新しい PR を待つ
6. **判断キューに載せない。** 局面は非ブロッキングな見え方。M21 の通知正本にもしない
7. **マージは人間のまま。** マージ済みになったら自動完了しない（9.4）

## 3. 作業局面カタログ

識別子は API が返す。日本語は UI。

| 局面 | 識別子 | いつ |
| --- | --- | --- |
| 未着手 | `unclaimed` | 決定済み。アクティブな着手なし。オープン / マージ済み PR なし |
| 実装中 | `in_progress` | 決定済み。アクティブな着手あり。オープン / マージ済み PR なし |
| レビュー中 | `in_review` | 決定済み。リンク済み PR が 1 件でも `open` |
| マージ済み | `merged` | 決定済み。`open` が無く、1 件でも `merged` |

優先順位（上から）: `open` あり → `in_review`。それ以外で `merged` あり → `merged`。それ以外で着手あり → `in_progress`。それ以外 → `unclaimed`。

- 複数 PR: どれか `open` ならレビュー中（残りがマージ済みでも）
- 着手が残ったままマージ済み: 局面は `merged`（位置は PR。着手バッジは残してよい）
- 完了・不採用・議論中・判断待ち、および対象外の型: `workPhase` は `null`

関数は純関数 `deriveWorkPhase`。入力 =（型、状態、着手の有無、PR state の列）。

## 4. 出す場所

| 面 | 載せ方 |
| --- | --- |
| スレッド一覧 | 各行に `workPhase`。主バッジは局面（レビュー中 等）。`decided` は二次バッジ |
| スレッド詳細 | 同じバッジ。完了ボタンはいまどおり `decided` の実装・レビュー |
| 非ブロッキング Inbox | 見出しは局面を正とする。既存 `kind`（`merge_wait` / `post_review`）は互換のため残す |
| `read_thread` / 朝の `situation.threads` と `open_threads` | `workPhase` を付ける（開いているスレッドはほぼ `null`） |
| ダッシュボード件数 | 変えない。件数の軸は合意状態のまま |

`unclaimed_decided` の定義は変えない（決定済み実装・着手なし・PR なし）。局面 `unclaimed` と同じ集合になる。

## 5. 完了条件

1. 決定済み実装で、PR なし・未着手 → 一覧が「未着手」
2. 着手だけ → 「実装中」
3. リンク済み PR が `open` → 「レビュー中」
4. その PR が `merged` → 「マージ済み」。スレッド状態は `decided` のまま
5. `complete_thread` のあと局面は出ない（「完了」）
6. 提案スレッドの決定済みは局面なし（「決定済み」のまま）
7. `pnpm test` / `pnpm typecheck` が緑

## 6. この設計で開けたまま残すもの

- 募集中・保留を合意状態に足すこと（9.2 の残り）
- Inbox の `kind` 廃止
- マージ済みでの自動完了、AI マージ（9.4）
- 局面での一覧フィルタ、ダッシュボード件数の内訳
- 局面変化を M21 の通知トリガーにすること
