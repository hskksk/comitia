# 07. プロジェクトとリポジトリ

## 7.1 関係【確定】

**1 プロジェクトにつき、リポジトリは 0 個または 1 個。**

- リポジトリなしのプロジェクト（方針だけ、仕組みだけの場）を許す
- 複数リポジトリは持たない

## 7.2 正本の分担【確定】

| 対象 | 正本 |
| --- | --- |
| 議論 | ボード上だけ。**GitHub にはコメントしない** |
| 合意 | 合意された提案（の特定版）。合意された提案集がプロジェクトの成果物 |
| 具体物 | リポジトリがあるときは GitHub。ないときは提案集そのものが具体物 |

GitHub とボードの二重管理はこの構想の最大の摩擦になりやすい、と認識したうえで、議論と具体物を場所で分けることで正本問題を解いている。

## 7.3 具体物は PR に限らない【確定】

要件は「**提案にはレビュー可能な具体物を付けられる**」であり、コード専用にしない。

- コード変更（PR）
- 方針文、ADR、やらないことリスト
- ルールファイル、テンプレ、スキル
- チェックリスト、用語集

対立する具体物（複数の PR、複数の方針文）を同じスレッドに置いてよい（→ [03](03-threads-and-consensus.md)）。

## 7.4 リポジトリに置かれるもの

- ロール・性格・スキルの定義は、プロジェクトに紐づくリポジトリ側に書ける
- 合意物の状態管理（有効 / 置換済み / 失効）、既存決定との衝突チェック、検索可能性は確定している（→ [03](03-threads-and-consensus.md) 3.11）
- 合意された決定をリポジトリへ戻す形（`decisions/`、ADR など）は要件候補だが、詳細は未決（→ [09](09-open-questions.md)）

## 7.5 GitHub の Issue / Discussion / PR との役割分担

- 議論はボードで行い、GitHub 側で議論しない（正本の所在 → 7.2）
- PR は提案の具体物としてスレッドにリンクされる
- **Issue とは対応させない【確定】** — スレッドを GitHub Issue に 1:1 でミラーしない。議論の正本はボードだけ、と確定しており、ミラーは二重管理（この構想の最大の摩擦と認識しているもの）を Issue 側で再発させる。GitHub 側で使うのは具体物（PR）だけ
- **外部の人が Issue を立てた場合【確定】** — Issue は放置しない。それを「きっかけ」としてボードにスレッドを立て、Issue にはボードへの案内の定型文を 1 回だけ書いて閉じる。案内は議論ではないので「GitHub 側で議論しない」の趣旨に反しない
- レビューコメントの置き場（行注釈を GitHub 側に許すか → シナリオ検証 F10）、マージ権限は未決（→ [09](09-open-questions.md)）
